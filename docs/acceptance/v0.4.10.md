# CCR v0.4.10 Acceptance Criteria

This release makes provider streaming and Claude Code compaction reliable without
client timeout workarounds. A checked item requires reproducible evidence on the
final release candidate; skipped live tests are not evidence.

## Behavior

- [x] Streamed OpenAI Chat Completions, OpenAI Responses,
  Anthropic-compatible, and managed computer-use provider traffic is translated
  incrementally into Anthropic SSE.
- [x] Each translated stream starts with a unique CCR message ID and a bounded
  input-token estimate suitable for Claude Code compaction accounting.
- [x] CRLF/LF SSE framing, delayed native `message_start`, terminal finish
  reasons, usage, text deltas, tool input, and malformed provider frames have
  explicit protocol handling.
- [x] Stream protocol, authentication, and tool-argument failures stay visible
  in-band with redacted errors; no silent provider or Claude fallback occurs.
- [x] Claude Code manual `/compact` and `--autocompact 100k` retain session
  state, reduce the continuation payload, and complete a post-compaction turn
  through a streaming-only OpenAI-compatible provider.

## Privacy and Security

- [x] No raw provider secret, authorization header, prompt, response, or tool
  argument is stored or printed by the new streaming and telemetry paths.
