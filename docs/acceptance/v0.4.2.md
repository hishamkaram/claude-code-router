# CCR v0.4.2 Acceptance Criteria

This is the release source of truth for account-aware subscription status,
quota classification, diagnostics, and resumable pool rotation. A checked item
requires reproduced evidence on the release candidate. Skipped live tests and
unsupported commands are not evidence.

## Account Truth

- [x] A subscription-pool launch status line shows the selected local
  `account=<name>` label and `limits=unknown`.
- [x] Explicit `--claude-account <name>` sends that label's stored OAuth token
  on model requests even when other account credentials are registered.
- [x] Local `claude-account test <name>` resolves the keychain credential
  without a network request.
- [x] `claude-account test --all --live` reports known quota windows and
  non-reversible identity fingerprints, and rejects duplicate subscription
  identities deterministically.
- [x] Live diagnostics fail visibly without exposing response bodies or
  credentials, do not forward credentials across redirects, and are never a
  routing dependency.
- [x] CCR does not parse shared Claude profile caches or present another
  profile's usage as selected-account data.
- [x] An existing user status line is replaced only in launch-generated
  settings, the launch records `statusline_state=replaced`, and user settings
  files remain byte-for-byte unchanged.
- [x] `--no-statusline` remains an explicit opt-out and warns that external or
  Claude-provided limits may belong to another local profile.
- [x] OAuth tokens and observer tokens are absent from CLI output and SQLite.

## Pool Rotation

- [x] Plain interactive pool launches rotate to the next account with
  `--continue` only after an explicit first-party rejected unified quota
  response.
- [x] Interactive `--resume <session-id>` launches, optionally combined with a
  named `--worktree`, rotate while replaying the original continuity arguments.
- [x] Launch output states whether automatic rotation is enabled and explains
  why it is disabled.
- [x] `--print`, explicit account selection, managed CUA, prompts, malformed
  resume/worktree arguments, and unknown passthrough shapes do not rotate.
- [x] Claude CLI, resume, worktree, settings, and process errors remain visible
  and never cycle through unrelated accounts.

## Quota State

- [x] A known representative claim with no fallback records
  `subscription_limit_<claim>` and prefers Anthropic's reset, capped at 24
  hours.
- [x] A model claim with fallback available or an unclassified rejection
  records a safe model/transient reason and uses a cooldown capped at five
  minutes.
- [x] Unknown provider header values cannot enter SQLite, logs, or CLI output.
- [x] Schema v8 clears only the legacy ambiguous `rate_limited` state and
  preserves explicit subscription, model, transient, and credential failures.
- [x] `claude-account list` shows the active cooldown deadline and safe reason.
