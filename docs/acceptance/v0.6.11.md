# CCR v0.6.11 Acceptance

Scope: restore the provider route recorded for the same native Claude Code
session, use immutable pinned route/model discovery, validate route and launch
inputs before starting Claude, make SQLite session route evidence authoritative,
persist immutable classifier decisions in SQLite v12, raise the Go floor to
1.26.9 for standard library vulnerability
fixes, and keep retry-bound test behavior deterministic. Unchecked remote and
publication items are not claims of completion.

Evidence date: 2026-10-11.

## Feature evidence

- [x] Resuming a native Claude Code session restores the provider route recorded
  for that same native session.
- [x] Resume routing uses immutable pinned route/model discovery.
- [x] Route, provider configuration, protocol, model kind, and provider secret
  identity are validated before launch.
- [x] Chat translation applies top-level Anthropic tool additions and removals
  before chronological message-level changes, matching the Responses path.
- [x] Launch summaries report the compatibility admitted before process start,
  even if provider configuration changes afterward.
- [x] SQLite v11 stores `sessions.active_protocol` and a non-secret
  `sessions.active_route_fingerprint`; the sessions row is authoritative for
  the exact provider/model configuration used by resume routing.
- [x] SQLite v12 stores each classifier request's immutable selection source and
  active alias. Conformance validates the captured decision without rebuilding
  concurrent state from event insertion order.
- [x] The Go floor is 1.26.9 for standard library vulnerability fixes.
- [x] Retry-bound behavior has deterministic test coverage and remains reliable
  under race execution.
- [x] Claude live conformance validates message and token-count classifier
  traces against each request's immutable routing decision. Ordered message
  transitions are isolated per known session and use launch order only when
  Claude does not expose request-level session identity.
- [x] Claude conformance requires a healthy route recorder and at least one
  classifier trace; the live fixture reconciles provider-observed classifier
  calls with persisted route events.
