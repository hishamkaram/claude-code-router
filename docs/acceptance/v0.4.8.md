# CCR v0.4.8 Acceptance Criteria

This release lets users without Claude authentication launch Claude Code
through a registered CCR provider while preserving the existing side-by-side
subscription and provider workflow for authenticated users. A checked item
requires reproducible evidence on the final release candidate; skipped live
tests are not evidence.

## Behavior

- [x] Default `auto` mode resolves to `preserve` when Claude authentication is
  detected.
- [x] Default `auto` mode resolves to `provider-only` when authentication is
  absent and a routable startup alias is selected explicitly.
- [x] Missing authentication and a missing startup alias fail before gateway,
  database, or Claude Code startup with actionable login/provider guidance.
- [x] Existing aliases are suggested through a read-only database lookup that
  does not create a database or parent directory.
- [x] Explicit `provider-only` mode requires a CCR startup alias and uses only
  the generated loopback gateway credential.
- [x] Legacy `gateway-token` behavior remains compatible and is documented as
  the legacy spelling for provider-only launches.
- [x] Explicit `preserve` and `subscription-pool` behavior remains unchanged.
- [x] Launch metadata, launch summaries, status output, and `ccr doctor` expose
  the resolved authentication mode.
- [x] Claude passthrough/help invocations remain outside CCR startup even though
  `auto` is the launch default.
- [x] Live CLI coverage proves a no-auth launch reaches a configured provider
  and proves the no-auth/no-model path never starts Claude Code.
- [x] Live conformance rejects non-affirmative `/model` results and verifies
  each registered/Anthropic route transition in order without depending on the
  rendered model label.

## Privacy and Security

- [x] Provider-only child environments remove inherited Anthropic API keys,
  custom auth headers, OAuth access/refresh tokens, and OAuth scopes.
- [x] Provider-only Claude Code receives only CCR's generated loopback
  credential; provider credentials remain inside the gateway.
- [x] Claude-auth detection recognizes supported environment and credentials
  file sources without treating CCR's own local token/header as first-party
  authentication.
- [x] Detection errors conservatively preserve authentication so uncertain OS
  credential-store state cannot silently disable a valid Claude login.
- [x] No raw provider secret, OAuth token, authorization header, prompt,
  response, or credential file content is added to logs or SQLite.

## Evidence

Verified locally on 2026-09-02 against installed Claude Code 2.1.240:

- Unit and integration coverage proves authenticated auto mode preserves Claude
  auth, no-auth auto mode selects provider-only only with an explicit routable
  alias, and no-auth/no-model exits before database or process startup.
- Platform-source tests prove macOS uses structured Claude CLI auth status,
  including its signed-out nonzero exit, while Linux and Windows use the local
  credentials file and environment auth short-circuits both paths.
- Initial review found explicit provider-only missing-model validation occurred
  after store startup. The requirement now runs in pre-store input validation;
  unit, focused live, and manual CLI proofs confirm the error leaves no database
  file and never starts Claude Code.
- A second review found that macOS Keychain auth could not be distinguished from
  a signed-out installation. Auto detection now consumes only the bounded,
  structured `loggedIn` result from `claude auth status --json`, with unit
  coverage and a live test wired to exercise the real path on macOS.
- A third review found credential-reader errors were classified as signed out
  and stale launches suppressed auth mode in `ccr doctor`. Reader errors now
  remain unknown/preserve, and doctor reports auth mode independently of stale
  launch health; both cases have regression coverage.
- Environment tests prove provider-only and legacy gateway-token launches clear
  inherited Anthropic API-key, custom-header, OAuth access/refresh, and scope
  variables while injecting only CCR's generated loopback credential.
- `go test -count=1 ./...` and `make check` pass. Maintainability reports zero
  hard violations, lint reports zero issues, and vulnerability scanning reports
  no vulnerabilities. A retry-bound gateway test also passes 20 consecutive
  focused race-detector runs after one host-contention timeout.
- The portable macOS helper protocol fixture and Docker browser image build and
  live CDP smoke test pass.
- The subscription-pool fixture passes all continuity and rate-limit cases. Its
  PTY readiness probe now waits for output quiescence instead of submitting
  input after the first byte, and the fixture explicitly models in-flight stale
