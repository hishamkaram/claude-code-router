# CCR v0.6.2 Acceptance

Scope: make Windows database access, strict OpenAI-compatible chat templates,
declared output limits, and cold local-model conformance reliable without
silent fallback. Unchecked publication items are not claims of completion.

Evidence date: 2026-09-17.

## Issue Verification

- [x] #83: Windows drive-letter SQLite URI construction is covered by
  platform-shaped unit tests, Windows CI, and a built-CLI smoke test using a
  nested Windows database path. UNC paths are rejected explicitly.
- [x] #84: OpenAI-compatible conversion folds top-level and late system text
  into one leading system message while preserving non-system message order.
  A strict provider integration test rejects any non-leading system message.
- [x] #85: Declared output limits are clamped and forwarded through Chat,
  Responses, and Anthropic-compatible routes with a response header and trace
  degradation event. Unknown-limit probes use a reasoning-safe budget, and a
  dedicated warm-up timeout covers cold model loading.

The external Qwen/llama.cpp endpoint from #84 was not available in this
environment. The strict-template contract is verified by the rejecting
provider integration test and by the live Claude Code fixture matrix; no
third-party Qwen endpoint run is claimed here.

## Known Limits

UNC database paths remain intentionally unsupported because the default SQLite
URI parser treats arbitrary URI authorities as invalid. Output-limit clamping
is visible and uses the configured capability as the safe upper bound; it does
not claim that an incorrectly configured capability can produce more output.
