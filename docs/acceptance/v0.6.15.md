  Native Windows plugin execution is not claimed.

### Native Completion Attribution

The first catalog-repair fixture target passed in 437.231 seconds. Its real
matrix completed 33 registered markers and their preceding first-party returns,
including the previously timing-out GLM Flash variants. Returning from Grok then
produced a 32-byte non-acknowledgement result. That run failed after 505.65
seconds (628.295 seconds for the selected package). The body was withheld; its
cause remains undiagnosed, and this is not a successful real-provider receipt.

The matrix now assigns each input a fresh UUID and joins modern native results
through `user_message_uuid` or membership in `user_message_uuids`. Native output
`uuid` is a distinct identity. A persistent cursor prevents skipping queued
errors; unmatched successes are counted, unmatched errors fail, and the final
stream is drained. Native trackers can retain earlier UUIDs, so unrelated or
repeated successful IDs alone are not errors. Older clients explicitly retain
serial completion, without claiming a UUID join. No modern fallback is allowed.
After each acknowledgement, the next exact marker also needs later successful
main inference evidence for the selected alias, provider, and backend. The
recovery-aware rule below distinguishes native recovery from validation;
classifier traffic cannot satisfy either proof.

### Native Transport Recovery Proof

Actual Opus 5.5 approved the catalog/source and documentation in task
`25221cb1d60ae0ad7821d0ccd1c0d51a`, accepted payload SHA-256
`037dfbc0c1ce55c07e50be764a7eb18c4b791018189224c24ebb2574d54a6b83`.
The later source-backed UI correction follows native display precedence.

The newly added streaming-only matrix rule used streaming as a proxy for main
inference. Native Claude deliberately recovers a failed stream by issuing the
same request without streaming to the same model. Rejecting that recovery does
not match the product's maximum-safe-degradation contract. Opus recommended the
following correction in task `7123d04a01dc0da8ecd98d29665fa9fd`, accepted payload
SHA-256 `25d337c343778db4bc5d0da5b814e4192de6c8bdc904de4e7c659fbbf6b4ae68`:

- A clean successful main stream remains the primary route proof.
- Recovery requires a post-acknowledgement failed main stream classified
  `provider_transport`, followed by a successful non-streaming request to the
  exact same requested ID, alias, provider, and backend. Non-transport errors,
  classifier traffic, stale/reversed pairs, and standalone validation requests
  cannot qualify. The exact marker and native input UUID requirements remain.
- Every provider represented in the switched matrix, including first-party
  Anthropic, must still prove at least one successful streaming marker. Earlier
  transport failures remain reported even when a later stream succeeds.
- Each recovered marker is explicitly reported as recovered, not as streaming.
  No test-side retries, extra probes, deadline changes, alias removals, or native
  retry-policy changes are introduced.

## Limits

Exported provider keys are available to trusted Claude tools/extensions, as
with plain Claude. CCR does not add file/keychain-resolved provider credentials
to the child environment. The original audit's conditional configured-native
non-stream error-body credential-echo finding is outside this environment and
catalog change; this receipt does not claim that finding has been remediated.
Compatible managed policy is required; managed routing conflicts and proxy
behavior are not solved here. Chat-only routes deliberately disable plugin
source discovery. Nested-session attribution and bare-mode lifecycle-hook
execution remain unverified. No new vision/CUA/executor capability is claimed.

Post-publication evidence will be appended after the exact-tag workflow,
draft verification and promotion complete.
