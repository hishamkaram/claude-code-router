The matrix now assigns each input a fresh UUID and joins modern native results
through `user_message_uuid` or membership in `user_message_uuids`. Native output
`uuid` is a distinct identity. A persistent cursor prevents skipping queued
errors; unmatched successes are counted, unmatched errors fail, and the final
stream is drained. Native trackers can retain earlier UUIDs, so unrelated or
repeated successful IDs alone are not errors. Older clients explicitly retain
serial completion, without claiming a UUID join. No modern fallback is allowed.
After each acknowledgement, the next exact marker also needs later successful
main inference evidence for the selected alias, provider, and backend. The
recovery-aware rule below distinguishes native recovery from validation;
classifier traffic cannot satisfy either proof.

inference. Native Claude deliberately recovers a failed stream by issuing the

- Recovery requires a post-acknowledgement failed main stream classified
  `provider_transport`, followed by a successful non-streaming request to the
  exact same requested ID, alias, provider, and backend. Non-transport errors,
  classifier traffic, stale/reversed pairs, and standalone validation requests
  cannot qualify. The exact marker and native input UUID requirements remain.
- Every provider represented in the switched matrix, including first-party
  Anthropic, must still prove at least one successful streaming marker. Earlier
  transport failures remain reported even when a later stream succeeds.
- Each recovered marker is explicitly reported as recovered, not as streaming.
  No test-side retries, extra probes, deadline changes, alias removals, or native
  retry-policy changes are introduced.
