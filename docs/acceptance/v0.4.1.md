# CCR v0.4.1 Acceptance Criteria

This is the release source of truth for the subscription-pool cooldown
classification fix. A checked item requires reproduced evidence. Skipped live
tests and unsupported commands are not evidence.

## Rate-Limit Classification

- [x] CCR rotates a subscription account only for a first-party
  `/v1/messages` HTTP 429 with
  `anthropic-ratelimit-unified-status: rejected`.
- [x] Missing, `allowed`, and unrecognized unified status values preserve the
  upstream response without cooling the account or terminating Claude Code.
- [x] `/v1/messages/count_tokens` 429 responses never cool or rotate an
  account.
- [x] Confirmed exhaustion prefers
  `anthropic-ratelimit-unified-reset` over `Retry-After`, subject to the
  existing bounded cooldown policy.
- [x] Registered Anthropic-compatible and OpenAI-compatible provider 429
  responses remain outside subscription-pool rotation.

## Recovery Command

- [x] `ccr claude-account clear-cooldown <name>` clears only the named
  account's cooldown and last-error metadata.
- [x] `ccr claude-account clear-cooldown --all` atomically clears cooldown and
  last-error metadata for every affected account and reports the count.
- [x] Missing names, extra names, invalid names, and combining a name with
  `--all` fail before opening SQLite.
- [x] Recovery preserves enablement, expiry, keychain references, and token
  values.
