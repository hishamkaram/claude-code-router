# CCR v0.4.3 Acceptance Criteria

This release corrects status-line ownership and subscription-pool continuity.
A checked item requires reproduced evidence on the release candidate.

## Status-Line Ownership

- [x] Subscription-pool launches preserve an existing Claude Code `statusLine`
  command and output through launch-generated credential-isolated settings.
- [x] Existing status-line commands inherit `CCR_CLAUDE_ACCOUNT` with the
  selected local account label.
- [x] OAuth, API-key, gateway, refresh, scope, and observer credentials are
  removed before an existing pool status-line command executes.
- [x] Windows uses a visible CCR status-line fallback instead of failing the
  pool launch when POSIX credential isolation is unavailable.
- [x] When no status line is configured, CCR can still inject its compact
  account-aware line.
- [x] A higher-precedence explicit `statusLine: null` disables an earlier
  command and remains disabled.
- [x] Subscription-pool launches reject passthrough `--settings` before
  account claim so an additional file cannot bypass credential isolation.
- [x] Launch-generated settings use mode `0600` in a mode-`0700` temporary
  directory on POSIX and the user-scoped temporary-directory ACL on Windows,
  never expose the existing command in process arguments, and are removed after
  Claude exits.
- [x] User settings files remain byte-for-byte unchanged.

## Pool Continuity

- [x] A confirmed first-party rejected quota response records the bounded
  cooldown and safe failure class before attempting rotation.
- [x] CCR resolves a usable replacement account before stopping the current
  Claude Code process.
- [x] If no replacement is usable, CCR keeps the current process and gateway
  open so Claude Code retains its native limit state and session.
- [x] A later rejected quota response retries pool selection without restarting
  CCR, allowing newly available accounts to participate.
- [x] Rotation-disabled launch shapes keep the current process open instead of
  turning quota state into a CCR process exit.
- [x] An initial launch with no usable account still fails visibly.
- [x] CCR never falls back to inherited Claude login, API-key authentication, or
  another provider.
- [x] OAuth tokens and observer tokens remain absent from output and SQLite.
