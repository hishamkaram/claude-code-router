# CCR v0.4.3 Acceptance Criteria

This release replaces process relaunch with transparent, same-process
subscription rotation. A checked item requires reproduced evidence on the final
release candidate.

## Same-Process Rotation

- [x] Claude Code receives only a generated loopback gateway credential; pooled
  OAuth tokens are absent from its environment and process arguments.
- [x] First-party `/v1/messages` requests use exactly the active account OAuth
  token from gateway memory, overriding incoming `Authorization` and
  `x-api-key` values.
- [x] Only a rejected unified limit with a recognized representative claim and
  no fallback triggers account cooldown and rotation.
- [x] Model-specific, unknown, token-count, registered-provider, temporary, and
  ambiguous limits do not cool or rotate an account.
- [x] A confirmed account-wide rejection is handled before downstream headers:
  CCR closes the rejected response, selects the next eligible account, and
  retries the same buffered request.
- [x] Rotation keeps one Claude launcher start, PID, gateway, session, pending
  turn, tools, browser connection, and managed CUA state.
- [x] Concurrent stale rejections rotate once. Requests from an old account
  generation retry the already-active generation and never mark it exhausted.
- [x] Rotation waits honor request cancellation and every retry response body
  has one explicit close path.
- [x] If no replacement is usable, CCR forwards Anthropic's original limit
  response and keeps Claude Code running; a later request retries selection.
- [x] `--claude-account` pins one account. Other launch shapes can rotate
  without resume argument rewriting or process replacement.
- [x] The active account is persisted on the existing launch record without a
  schema migration.
- [x] CCR never falls back to inherited Claude login, API-key authentication, or
  another provider.

## Status And Secrets

- [x] Injected CCR status lines read the current account from the gateway after
  rotation.
- [x] Existing status-line commands keep their command and output, receive a
  dynamically resolved `CCR_CLAUDE_ACCOUNT`, and cannot read OAuth, API-key,
  refresh, scope, gateway, or observer credentials.
- [x] Windows uses a visible CCR status-line fallback when POSIX credential
  isolation is unavailable.
- [x] A higher-precedence explicit `statusLine: null` remains disabled.
- [x] Launch-generated settings remain private, absent from process arguments,
  removed after exit, and do not modify user settings files.
- [x] OAuth values remain absent from stdout, stderr, errors, SQLite, status
  JSON, traces, test output, and documentation.
