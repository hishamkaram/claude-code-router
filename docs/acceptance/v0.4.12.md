# CCR v0.4.12 Acceptance

Date: 2026-09-07. Verification host: Linux.

## Behavior

Ordinary tool image results on Responses routes are encoded as multimodal
`function_call_output` content rather than rejected as requiring native computer
use. Image bytes, URLs, text ordering, and the original call ID are preserved.
Native computer screenshot handling remains separate. Text-only results retain
their existing string representation; invalid and unsupported content remains
an explicit error.

The wire format follows the official
[OpenAI function-calling documentation](https://developers.openai.com/api/docs/guides/function-calling).

## Evidence

- Unit regressions cover image-only results, mixed text/images, multiple images,
  empty text, unchanged text-only output, missing call IDs, invalid images, and
  unsupported content. Native computer and ordinary function outputs remain
  distinct even when both tools are present.
- `TestLiveFixtureResponsesImageToolResult` passed using real Claude Code and a
  real MCP subprocess returning a deterministic image. The provider fixture
  verified the image content and call ID before returning the final response.
- Full unit and race suites, vet, lint, vulnerability checks, and maintainability
  passed. The full live-tagged suite exited zero. Independent review reported
  zero actionable regressions and independently passed the new live fixture.
- The required image-result live case executed without skips. Unrelated opt-in
  cases in the full suite were not enabled.

## Limits

The exact GPT provider endpoint from the reported failure was not configured on
the verification host. The live proof validates CCR with real Claude Code and a
deterministic Responses provider fixture, not that external endpoint.
