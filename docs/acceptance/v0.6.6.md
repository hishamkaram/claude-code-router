# CCR v0.6.6 Acceptance

This file is the release source of truth. Checked items require reproducible
evidence. Skipped live tests are not evidence.

Scope: provider-backed startup aliases use provider authentication in automatic
auth mode even when Claude Code subscription authentication is present, while
native Claude authentication remains available for no-model launches and
first-party Anthropic aliases without a provider credential.

Evidence date: 2026-09-24.

## Behavior

- [x] Provider-backed startup aliases use provider-only authentication in
  automatic mode independently of detected Claude login state; no-model and
  first-party Anthropic paths preserve Claude auth when applicable. Covered by
  PR [#107](https://github.com/hishamkaram/claude-code-router/pull/107),
  including `TestLiveAutoProviderAliasIgnoresDetectedClaudeAuth`.
- [x] Incoming Claude credentials are forwarded only to the official Anthropic
  endpoint. Provider aliases use their configured provider credentials (PR
  [#107](https://github.com/hishamkaram/claude-code-router/pull/107)).
- [x] Live provider-route acceptance checks completed non-empty turns and
  verifies the configured alias resolves to the traced provider and model,
  rather than assuming response wording identifies the route. Agent/WebFetch
  stream coverage accepts both current Agent and legacy Task tool events; see
  PR [#108](https://github.com/hishamkaram/claude-code-router/pull/108).

## Privacy and Security

- [x] The provider-auth change neither logs nor prints raw credentials, and
  Claude credentials are forwarded only to Anthropic's official endpoint.
  PR #107 covers provider-auth isolation; release records contain no
  credential values.
