# CCR v0.6.15

Claude Code workloads now retain the caller's exported environment, including
credentials also referenced by registered providers. Hooks, plugins, MCP servers
and their children can share those variables. CCR does not read shell startup
files or create a separate user profile. CCR does not export file/keychain-
resolved provider keys or pooled account OAuth credentials to that environment.

CCR keeps its explicit authentication overrides and withholds the designated
CUA external-executor token. Windows environment matching is case-insensitive.
A names-only launch notice explains which inherited variables CCR controls.

Non-secret gateway, provider-selection and model controls are pinned in Claude's
launch settings so user/project settings cannot redirect ordinary routing.
Credentials and custom headers never enter that generated settings file.
Authentication conflicts produce a visible native 401; the gateway response
includes names-only guidance, whose display by Claude is unverified. User
`--settings` overrides are rejected before auth or database work; native settings
sources still apply.

Registered model IDs now populate Claude's native `modelPicker` catalog as well
as its allowlist. On verified Claude Code 2.1.310 and 2.1.311, `/model` accepts
those IDs after native policy checks without waiting for an inference probe.
The first real turn still must reach the selected provider; provider failures
remain visible and never silently fall back to Anthropic. User picker rows,
their metadata and built-in-row preference are preserved, subject to enabled
settings sources and higher managed policy. Claude Code 2.1.209 keeps legacy
inference validation and remains dependent on provider latency during selection.

CLI compatibility: place `--setting-sources` before other forwarded Claude
options. Ambiguous later tokens are rejected before runtime side effects;
use inline option values for literal flag-like prompt text. Existing saved
jobs with the old ordering require resubmission rather than silent rewriting.

Compatible managed policy is required. Proxy behavior and managed routing
overrides remain documented limitations. Chat-only routes deliberately disable
plugin discovery. See [environment inheritance](../routing.md#user-environment-and-plugins).

Live regressions use synthetic hooks, MCP servers and grandchildren. They cover
foreground, print, managed-job and resume execution plus native settings precedence.
