# CCR v0.4.7

## Highlights

- Claude Code auto-mode safety classifier traffic now follows the active CCR
  model alias instead of consuming the preserved Anthropic subscription.
- Classifier routing follows in-session `/model` changes and remains isolated
  between concurrent Claude sessions.
- An unavailable active alias fails visibly; CCR never silently falls back to
  first-party Anthropic for that classifier request.

## User-Visible Changes

When a CCR alias is selected at launch or through `/model`, auto-mode classifier
messages and token-count requests use that alias's registered provider. Normal
model responses continue to expose the model name requested by Claude Code.

If no CCR alias is active for a Claude session, CCR preserves the existing
behavior and routes the classifier's requested first-party model. If an active
alias is blocked, removed, unsupported, missing credentials, or rejected by its
provider, the request fails with a visible classifier routing error instead of
using the Anthropic subscription.

Classifier traffic is visible in route traces as `auto_mode_classifier` and
`auto_mode_classifier_count_tokens`.

## Upgrade

```bash
brew upgrade hishamkaram/tap/claude-code-router
ccr version
ccr doctor
```

No database migration or model reconfiguration is required.

## Privacy and Security

- Classifier prompts and responses are not added to trace storage; only the
  dedicated operation name and existing redacted route metadata are recorded.
- Provider secret storage and authentication behavior are unchanged.
- Failed selected-alias routing cannot expose classifier traffic to the
  preserved Anthropic subscription through an implicit fallback.

## Compatibility

- Classifier routing is covered for OpenAI Chat Completions, OpenAI Responses,
  and Anthropic-compatible providers.
- The active alias is tracked per Claude session from the
  `x-claude-code-session-id` header used by Claude Code.
- Explicit CCR aliases on classifier requests take precedence over older cached
  session state, while blank session IDs are never stored as a shared key.
- Startup aliases apply to new sessions until that session selects another CCR
  alias or intentionally returns to a first-party model.
- The macOS computer-use helper remains a source-built unsigned preview and is
  not included in Homebrew or GoReleaser archives.

## Verification

Release evidence is recorded in `docs/acceptance/v0.4.7.md`, including direct
gateway tests, all three provider protocols, race coverage, the complete live
suite, and real Claude Code CLI model-switch, Agent, and workflow paths.

## Known Limits

- Classifier recognition follows Claude Code's current structured system-prompt
  signature. Pinned and latest Claude Code fixture jobs act as compatibility
  canaries for future prompt changes.
- Existing workers may retain their spawn-time route where Claude Code does not
  issue new work under the updated session selection.
