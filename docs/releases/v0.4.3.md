# CCR v0.4.3

## Highlights

- Subscription-pool launches keep your existing Claude Code status-line
  behavior while removing credentials from that command's environment.
- CCR claims the next usable account before stopping Claude Code after a
  confirmed subscription limit.
- If every replacement is unavailable, Claude Code stays open with its native
  limit state instead of CCR terminating the session.

## User-Visible Changes

CCR keeps an existing `statusLine` command and its output in subscription-pool
mode. A launch-only credential-isolation wrapper removes OAuth, API-key,
gateway, refresh, scope, and observer credentials before execution. The
existing command still receives the selected local account label:

```text
CCR_CLAUDE_ACCOUNT=personal
```

On Windows, CCR visibly bypasses the existing command for that launch and uses
its account-aware line because the POSIX isolation wrapper is unavailable.

When no status line is configured, CCR can still inject its compact
account-aware line. A higher-precedence explicit `statusLine: null` remains
disabled. On POSIX, generated launch settings use a mode-`0600` file inside a
mode-`0700` temporary directory; Windows uses the user-scoped temporary
directory ACL. The file is removed after Claude exits, so the existing command
is not exposed in process arguments. User settings files remain unchanged.

For eligible interactive launches, confirmed account exhaustion still rotates
to another subscription:

```bash
ccr launch --auth-mode subscription-pool
```

CCR now resolves the replacement account and its keychain credential before
stopping Claude Code. If no replacement is usable, the current Claude process
and gateway remain open so the native Claude limit state and session are
preserved. A later confirmed rejection retries pool selection, allowing an
account that was added, refreshed, or became available to participate.

## Upgrade

```bash
brew upgrade hishamkaram/tap/claude-code-router
ccr version
ccr doctor
ccr claude-account list
```

No database migration or account re-import is required.

## Privacy and Security

- OAuth credentials remain in the OS keychain and are never stored raw in
  SQLite or printed.
- CCR never falls back to inherited Claude login, an Anthropic API key, or
  another provider when the pool has no usable replacement.
- Existing status-line commands receive only the local account label through
  `CCR_CLAUDE_ACCOUNT`; authentication and observer credentials are scrubbed,
  and quota data is not inferred from a shared profile.

## Compatibility

- Each Claude Code process still has one fixed OAuth identity. Account rotation
  starts a replacement process only after a replacement is ready.
- Rotation remains disabled for one-shot, explicit-account, managed-CUA,
  prompt, and unsupported passthrough launch shapes. Those processes also stay
  open on confirmed quota exhaustion.
- An initial pool launch with no usable account fails visibly.
- Temporary or ambiguous HTTP 429 responses remain with Claude Code and do not
  cool or rotate an account.
- Windows pool launches with an existing status line use CCR's safe
  account-aware line instead of failing or exposing launch credentials.

## Verification

Release evidence is recorded in `docs/acceptance/v0.4.3.md`. Coverage includes
the full deterministic and race gates, subscription-pool fixtures, real Claude
PTY replacement and all-limited continuity, secret redaction, hosted CI, and an
issue-free Codex review.

## Known Limits

- Claude Code OAuth tokens do not provide a stable supported account-scoped
  quota API. CCR reacts only to confirmed first-party quota rejection and
  reports independently loaded quota as untrusted.
- An interrupted user turn is not replayed automatically because replay could
  repeat tool side effects.
- The macOS computer-use helper is source-built only, is not shipped in
  Homebrew or GoReleaser archives, and remains an unsigned preview.
