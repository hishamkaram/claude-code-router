# CCR v0.4.1

## Highlights

- Subscription-pool rotation now requires Anthropic's explicit unified
  usage-limit rejection instead of treating every first-party HTTP 429 as
  account exhaustion.
- Temporary and ambiguous 429 responses remain with Claude Code for its normal
  retry behavior and do not cool every registered account.
- False or stale cooldown state can be cleared without re-importing keychain
  credentials.

## User-Visible Changes

Inspect account state, verify it independently, then clear one or all stale
cooldowns:

```bash
ccr claude-account list
ccr claude-account show main
ccr claude-account test main
ccr claude-account clear-cooldown main
ccr claude-account clear-cooldown --all
```

`clear-cooldown` removes only `cooldown_until` and `last_error` metadata. It
does not contact Anthropic, enable an account, extend expiry, or modify OAuth
tokens and keychain references.

## Compatibility

- Confirmed exhaustion requires a first-party `/v1/messages` HTTP 429 with
  `anthropic-ratelimit-unified-status: rejected`.
- Missing, `allowed`, and unrecognized unified statuses are forwarded
  unchanged without CCR process termination or account rotation.
- Token-count, registered Anthropic-compatible provider, and OpenAI-compatible
  provider 429 responses remain outside subscription-pool rotation.
- For confirmed rejection, the unified reset timestamp is preferred over
  `Retry-After` under CCR's existing bounded cooldown policy.

## Upgrade

```bash
brew upgrade hishamkaram/tap/claude-code-router
ccr version
ccr doctor
ccr claude-account list
```

Accounts cooled by v0.4.0 remain cooled until their timestamp expires. After
upgrading and independently confirming they are usable, clear stale state with
`ccr claude-account clear-cooldown --all`.

## Privacy and Security

- Recovery changes SQLite failure metadata only.
- OAuth tokens remain in the OS keychain and are never printed or stored raw in
  SQLite.
- Automatic rotation remains visible and never silently falls back to another
  identity or provider.

## Verification

Release evidence is recorded in `docs/acceptance/v0.4.1.md`. Required coverage
includes deterministic and race gates, confirmed-rejection and temporary-429
live fixtures, the configured real-provider matrix, an issue-free Codex review,
the hosted fixture matrix, release archive checksums and provenance, and signed
GHCR browser-image verification.

## Known Limits

- `ccr claude-account test <name>` validates the local keychain credential; it
  does not query current subscription quota.
- The unified subscription-limit headers are consumed from observed current
  Claude Code traffic and are not part of Anthropic's public API rate-limit
  header documentation. Unknown signals deliberately degrade to Claude Code's
  own retry handling.
- The macOS computer-use helper remains a source-built unsigned preview. It is
  not included in Homebrew or GoReleaser archives.
