# CCR v0.6.6

## Highlights

Provider-backed startup aliases now use their configured provider
authentication in automatic launch mode, independently of whether Claude Code
subscription authentication is present. This addresses launches where CCR was
configured for a non-Anthropic provider but Claude Code still prompted for
subscription login.

## User-Visible Changes

- `ccr launch --model <alias>` uses that alias's provider credentials when the
  alias routes to a configured provider, even if a Claude subscription login
  is detected.
- Launches without an explicit model keep using the existing Claude
  authentication. First-party Anthropic aliases without a provider credential
  can also continue using Claude authentication.
- Incoming Claude credentials are forwarded only to Anthropic's official
  endpoint; other providers use their configured credentials.

## Upgrade

No configuration migration is required. Existing provider aliases continue
using their configured credentials. Update the CCR binary or Homebrew formula
to v0.6.6, then verify the installation with `ccr version` and `ccr doctor`.

## Privacy and Security

The auth-mode selection does not copy Claude subscription credentials to
non-Anthropic providers. Provider secrets remain in CCR's existing protected
credential storage and are not printed or logged.

## Compatibility

The change applies to provider-backed startup aliases in automatic auth mode.
It preserves native Claude authentication for launches without an explicit
model and for first-party Anthropic aliases that do not have a provider
credential. Per-session model routing behavior is unchanged.

## Verification

The acceptance record documents provider-auth tests, the local real-provider
matrix, pull-request CI, and release artifact verification:
[v0.6.6 acceptance](../acceptance/v0.6.6.md).

The live-route test improvements in PR #108 validate the selected provider and
model from gateway trace evidence and cover Agent/WebFetch stream completion;
they strengthen verification without changing runtime routing behavior.

## Known Limits

This release does not claim real vision, computer-use, or executor-provider
coverage. The macOS computer-use helper remains source-built only and is not
included in the Homebrew formula or GoReleaser archives; it remains an unsigned
preview.
