# CCR v0.4.10

## Highlights

- CCR now translates supported provider streams incrementally, so Claude Code
  receives Anthropic-compatible SSE as provider data arrives instead of after a
  complete response has been buffered.
- Manual `/compact` and automatic compaction retain reliable token accounting
  through OpenAI-compatible providers.
- Stream errors remain visible and redacted, with terminal stream telemetry for
  diagnosis rather than silent fallback.

## User-Visible Changes

OpenAI Chat Completions, OpenAI Responses, Anthropic-compatible, and managed
computer-use routes preserve streaming end to end when Claude Code requests it.
CCR emits an Anthropic `message_start` with a bounded input-token estimate before
the provider response arrives, then relays text, tool input, terminal usage, and
completion events as they become available.

This removes the buffered-response failure mode that could leave compaction
waiting for a provider or gateway to finish a large summary. It does not change
provider selection, retry ambiguous generation requests, or add a client-side
timeout override.

## Upgrade

```bash
brew upgrade hishamkaram/tap/claude-code-router
ccr version
ccr doctor
```

No database migration or provider reconfiguration is required. Restart long-lived
CCR launches after upgrading so they use the new gateway binary.

## Privacy and Security

- Provider credentials, authorization headers, prompts, and tool arguments are
  not written to stream telemetry or error messages.
- Malformed provider frames and invalid streamed tool arguments terminate the
  stream visibly with a redacted in-band error.
- Native first-party authentication failures update CCR's authentication state
  without revealing upstream error text.

## Compatibility

- Non-stream requests retain their existing buffered request-response behavior.
- OpenAI Chat and Responses streams accept normal CRLF or LF SSE framing.
- Native Anthropic streams receive SSE comments while idle before the upstream
  `message_start`, then normal Anthropic pings after a protocol event is sent.
- Provider streams without a valid terminal completion are rejected instead of
  being reported as a successful `end_turn`.
