# CCR v0.6.7

## Model-family routing for agents and skills

CCR now uses Claude Code's supported family-default settings during a
provider-backed launch. Agents, skills, workflows, and teammates that declare
`model: opus`, `model: sonnet`, or `model: haiku` are resolved by the gateway
against the active CCR alias for that Claude session.

The routing follows `/model` changes in the same session. Selecting another
CCR alias moves later family requests to that provider model; selecting a
first-party Claude model restores native Anthropic routing. If the active CCR
alias is blocked, deleted, or otherwise unroutable, CCR returns the error
instead of silently falling back to Claude.

The family settings are written only to CCR's private launch overlay. A launch
without a CCR startup alias does not override Claude Code's native defaults,
and user settings files are not modified.

CCR also accepts the current Claude Code `safeguards` request marker on
translated OpenAI-compatible routes. Because those providers cannot execute
Anthropic safeguard semantics, CCR omits the marker upstream and reports the
visible degradation with `X-CCR-Ignored-Anthropic-Fields`.

See the [acceptance record](../acceptance/v0.6.7.md) for unit, CLI, and live
Claude Code evidence.

## Upgrade

No persistent configuration changes are required. Upgrade CCR to v0.6.7 and
start a new `ccr launch --model <alias>` session to enable family routing for
that provider-backed launch.

## Compatibility and security

Family routing uses reserved, non-secret model identifiers inside the
launch-only settings overlay. Provider credentials remain in the existing
secret paths and are not logged, printed, or persisted by this feature.
