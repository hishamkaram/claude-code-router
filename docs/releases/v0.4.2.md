# CCR v0.4.2

## Highlights

- Subscription-pool launches now identify the selected local account label
  without presenting shared Claude profile quota as that account's usage.
- Anthropic limit responses are classified by quota claim and fallback
  availability, so account-wide exhaustion and short model limits no longer
  share one inaccurate cooldown.
- `claude-account test --all --live` reports advisory quota windows and detects
  account labels backed by the same subscription.
- Quota rejections can rotate interactive resumed sessions, including named
  worktrees, while preserving their continuity arguments.
- Launch output states whether automatic rotation is available and why an
  unsupported launch shape will not rotate.

## User-Visible Changes

Pool launches install an account-aware status line for the launched process:

```text
CCR | account=personal | limits=unknown | route=...
```

`limits=unknown` is intentional. CCR does not make routing depend on Claude
Code's private advisory quota service and does not reuse quota from a shared UI
profile or local cache. Existing user settings files are not changed. Use
`--no-statusline` to opt out for one launch.

Run an explicit best-effort account check when you need current quota details:

```bash
ccr claude-account test --all --live
```

The command resolves each keychain credential, reports known five-hour,
seven-day, and model quota windows, and compares non-reversible identity
fingerprints. A duplicate fingerprint means two labels use the same
subscription. A private-service failure is reported and never affects routing.

Automatic rotation supports plain interactive launches and resumable sessions:

```bash
ccr launch --auth-mode subscription-pool
ccr launch --auth-mode subscription-pool \
  --worktree mcp-stateless-ha \
  --resume fa605631-8a49-4afa-9888-ea4f7f26f26b
```

After a rejected first-party quota response, CCR starts a new Claude Code
process with the next eligible account. A known account-wide claim with no
fallback keeps Anthropic's reset, capped at 24 hours. Model-specific or
unclassified rejections use a transient cooldown capped at five minutes. Plain
launches use `--continue`; explicit resume and worktree arguments are replayed
unchanged.

## Compatibility

- Rotation remains disabled for `--print`, an explicit `--claude-account`,
  managed CUA, prompts, malformed continuity arguments, and unknown passthrough
  shapes.
- HTTP 429 responses without Anthropic's explicit rejected unified status
  remain with Claude Code and do not cool or rotate an account.
- CCR does not replay an interrupted user turn because doing so could repeat
  tool side effects. Continue an unfinished turn after the resumed session
  opens.
- Account labels identify model-request credentials stored by CCR. Claude
  Code's visible profile may still be the shared local login.

## Upgrade

```bash
brew upgrade hishamkaram/tap/claude-code-router
ccr version
ccr doctor
ccr claude-account list
ccr claude-account test --all --live
```

Schema v8 clears only legacy cooldown rows whose reason was the ambiguous
`rate_limited` marker. Explicit subscription, model, transient, credential,
disabled, and expiry state is preserved. The migration is automatic and no
account re-import is required.

## Privacy and Security

- OAuth tokens remain in the OS keychain and are never printed or stored raw in
  SQLite.
- Pool launches remove inherited Anthropic and Claude OAuth credentials before
  injecting the selected account token.
- Status and trace output contain only local account labels and redacted launch
  metadata.
- User settings are read to construct launch-only settings and are not
  modified.

## Verification

Release evidence is recorded in `docs/acceptance/v0.4.2.md`. Required coverage
includes deterministic and race gates, real Claude selection and rotation,
resumed-worktree relaunch, secret redaction, an issue-free Codex review, the
hosted fixture matrix, and release artifact verification.

## Known Limits

- Live identity and quota diagnostics use Claude Code's private advisory
  services. They can become unavailable or change independently of CCR;
  `claude-account test <name>` remains a local-only credential check and pool
  routing does not depend on live diagnostics.
- Automatic rotation starts another Claude Code process; it cannot replace
  credentials inside the existing process.
- The macOS computer-use helper remains a source-built unsigned preview. It is
  not included in Homebrew or GoReleaser archives.
