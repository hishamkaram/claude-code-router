# CCR v0.6.4

## ToolSearch deferred-tool activation

CCR now carries a declared deferred tool into the upstream request after
Claude Code loads it through ToolSearch on the OpenAI Chat Completions route.
The route reads `tool_reference` blocks from `tool_result` content and applies
those changes in conversation order, so the provider sees the same active tool
set that Claude Code was told to use.

Undeclared names in ToolSearch `tool_reference` results are ignored. Later tool
removals still win, while system-block additions and removals continue to
validate tool names and report unknown-tool errors visibly.

This closes the gap between the Chat Completions and Responses translators. In
the affected flow, Claude Code could successfully load a deferred tool and ask
for it while the provider request still omitted that tool.

See the [acceptance record](../acceptance/v0.6.4.md) for the reproducible
regression and live Claude Code evidence.

## Upgrade

No configuration changes are required. Upgrade the CCR binary or Homebrew
formula to v0.6.4 and restart the local gateway so the new translator is used.

## Compatibility and security

The change is limited to declared ToolSearch references in translated OpenAI
Chat Completions requests. Provider credentials and request secrets are not
logged or persisted by this feature.
