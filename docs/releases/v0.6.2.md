# CCR v0.6.2

## Local and Strict Provider Compatibility

CCR now handles several compatibility boundaries that made otherwise usable
local providers fail in real Claude Code sessions.

Windows database paths are converted to SQLite's drive-letter URI form, so
commands such as `ccr doctor` and `ccr init` can open the default database.
Unsupported UNC database paths fail explicitly with guidance to use a local
drive path.

OpenAI-compatible Chat Completions requests now combine top-level and
mid-conversation system instructions into one leading system message. User,
assistant, and tool messages retain their original order, keeping strict chat
templates such as Qwen3's valid while preserving the environment instructions
sent to subagents.

When a model advertises a lower maximum output than Claude Code requests, CCR
now clamps the forwarded request instead of rejecting the alias. The response
exposes `X-CCR-Output-Limit`, and the trace records the requested and applied
values as a visible compatibility degradation. Chat Completions, Responses,
and Anthropic-compatible routes apply the same rule.

Provider conformance now warms a model separately from steady-state probes.
The warm-up phase has its own five-minute timeout by default, and text/stream
probes use a reasoning-safe budget when the provider has not declared an output
limit. Both timeouts can be configured from the CLI.

See the [acceptance record](../acceptance/v0.6.2.md) for reproducible evidence.
