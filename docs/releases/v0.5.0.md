# CCR v0.5.0

## Durable Detached Jobs

```bash
ccr launch --model <alias> --detach -p --prompt-file prompt.txt
ccr status <job_id> --json
ccr cancel <job_id> --json
```

Detached launch returns a durable job/session receipt without waiting for model
execution. Records and private stdout/stderr logs survive the launching CLI.
Status includes exit information, cancellation state, and cleanup evidence.
Cancellation accepts only job IDs and is idempotent.

## Containment And Limits

- Linux uses detected systemd user scopes, with gated workload admission.
- macOS and Linux without a usable user manager use a degraded native path.
- Cleanup coverage is independent of terminal status. Native same-user execution
  cannot exclude D-Bus escape and does not claim complete cleanup.
- Failed scope control never enables process-ID or process-group signal fallback.
- Owner loss does not replay work or authorize recovery signals.
- Detached input requires a regular prompt file. A standalone second `--` is
  rejected because Claude may interpret it as an option value; foreground
  passthrough is unchanged.
- Migration of a separate runner is not included in this release.

Logs can contain sensitive workspace content. Inspect them before sharing.
The macOS computer-use helper remains a source-built unsigned preview; it is
not included in Homebrew or release archives.

## Idle Connection Reliability

Gateway-owned upstream connections are retired after at most 15 idle seconds.
This prevents a new turn from inheriting an almost-expired idle health probe.
Active-stream pings, deadlines, and shorter configured idle limits remain
intact. No failed POST is replayed. Injected HTTP clients remain caller-managed.
The correction addresses [issue #73](https://github.com/hishamkaram/claude-code-router/issues/73).

## Known Routing Issue

An intermittent duplicate response with Grok 4.6 remains under investigation
in [issue #72](https://github.com/hishamkaram/claude-code-router/issues/72).
The recheck has not reproduced that exact duplication, but a later full-session
run returned a different marker than requested. No fix is claimed and repeated
text is not suppressed. Publication remains blocked on the required live gate;
see the acceptance record for evidence.
