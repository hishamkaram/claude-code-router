# CCR v0.4.9

## Highlights

- Manual `/compact` and automatic Claude Code compaction now work through
  OpenAI-compatible Chat Completions providers without forcing the upstream
  generation into buffered mode.
- OpenAI streaming text, tool-call fragments, finish reasons, and terminal
  usage are decoded with explicit response-size bounds before CCR performs its
  existing Anthropic response conversion.
- Providers that return a normal JSON completion despite `stream: true` remain
  supported.

## User-Visible Changes

CCR now preserves Claude Code's streaming preference when routing an Anthropic
Messages request to OpenAI Chat Completions and requests terminal token usage
with `stream_options.include_usage`. This allows LiteLLM and other compatible
gateways to send response headers and data while a large compaction summary is
being generated, instead of leaving the remote HTTP request idle until the
entire summary is complete.

The change applies to ordinary streamed turns as well as manual and automatic
compaction. It does not detect or rewrite compaction prompts, retry ambiguous
completion POSTs, or switch to another provider.

## Upgrade

```bash
brew upgrade hishamkaram/tap/claude-code-router
ccr version
ccr doctor
```

No database migration or provider reconfiguration is required. The configured
context window should still match the provider model's real input limit.

## Privacy and Security

- Provider credentials remain inside CCR and are not added to stream events,
  errors, logs, or SQLite.
- Provider error events are bounded and sanitized with the existing secret
  redaction rules.
- Incomplete, malformed, and oversized streams fail visibly; partial output is
  not accepted as a completed response.
- CCR does not retry an ambiguous streamed generation, preventing duplicate
  inference cost.

## Compatibility

- Non-stream Anthropic requests continue to use non-stream OpenAI JSON
  completions and omit `stream_options`.
- Streamed requests accept standards-compatible SSE and retain the existing
  JSON fallback for providers that ignore the stream preference.
- Fragmented text, current and legacy function calls, multiple tool calls,
  usage-only terminal chunks, `[DONE]`, and a terminal finish event without
  `[DONE]` are handled.
- Explicit Anthropic API `compact_20260112` context-management edits remain
  unsupported on OpenAI-compatible routes. Claude Code's client-managed
  compaction path is supported.

## Verification
