# CCR v0.4.5

## Highlights

- OpenAI-compatible routes no longer reject valid Anthropic assistant text
  blocks solely because they carry citation metadata.
- The assistant text remains available to the provider, while unsupported
  citation metadata is dropped explicitly and reported through the existing
  compatibility header.
- A live Claude Code fixture proves the behavior across a `/model` switch in
  the same session.

## User-Visible Changes

When Claude Code sends prior assistant history containing Anthropic `citations`
to an OpenAI-compatible Chat Completions route, CCR now preserves the text and
omits only the unsupported citation metadata. The response includes:

```text
X-CCR-Ignored-Anthropic-Fields: messages[].content[].citations
```

The marker identifies compatibility degradation without exposing citation
contents or provider credentials. First-party Anthropic and Anthropic-compatible
routes retain their existing citation handling. Unknown fields remain strict,
as do citations in user, system, and tool-result text blocks.

## Upgrade

```bash
brew upgrade hishamkaram/tap/claude-code-router
ccr version
ccr doctor
```

No database migration or provider reconfiguration is required.

## Privacy and Security

- Citation contents are not logged, persisted, or copied into the downstream
  OpenAI-compatible request.
- The compatibility header contains only the name of the ignored field.
- Provider secrets remain outside request diagnostics and are unaffected by the
  content conversion change.

## Compatibility

- OpenAI-compatible Chat Completions routes preserve assistant text and drop
  unsupported `citations` metadata with visible degradation.
- Anthropic Responses conversion preserves assistant text and accepts citation
  metadata without forwarding unsupported fields to the provider.
- First-party Anthropic and Anthropic-compatible routes keep their existing
  native content behavior.
- Unknown assistant fields and unsupported fields in other content roles still
  fail visibly instead of being silently discarded.

## Verification

Release evidence is recorded in `docs/acceptance/v0.4.5.md`. It includes unit,
race, vet, lint, vulnerability, full tagged live-suite, and live Claude Code
model-switch evidence, plus the hosted CI and post-tag artifact evidence added
after publication.

## Known Limits

- OpenAI-compatible Chat Completions cannot receive Anthropic citation
  structures through this route; only the assistant text is preserved.
- The macOS computer-use helper is source-built only, is not shipped in Homebrew
  or GoReleaser archives, and remains an unsigned preview.
