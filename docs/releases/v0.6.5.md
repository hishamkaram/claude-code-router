# CCR v0.6.5

## Session-scoped Claude model routing

CCR now keeps model selection isolated to each Claude Code session launched
through CCR. Changing `/model <alias>` in one session no longer changes the
selected model or profile used by a separate native Claude Code session.

CCR launches Claude Code with a private profile, preserving native Claude
state while allowing CCR-owned session state to survive supported detached
continuations. Eligible Agent, Task, and Workflow child requests follow the
active CCR model alias when they can be routed safely. Unsafe or expired child
routing is rejected visibly instead of silently falling back to Claude.

See the [acceptance record](../acceptance/v0.6.5.md) for live Claude Code,
provider-matrix, CI, and release-artifact evidence.

## Upgrade

No configuration changes are required. Upgrade the CCR binary or Homebrew
formula to v0.6.5 and launch Claude Code through CCR to use session-scoped
routing. Native Claude Code launches remain independent of CCR's selected
model.

## Compatibility and security

The change preserves the native Claude profile and uses CCR-owned profile
state for CCR-launched sessions. Provider credentials are not logged or
printed. Child requests that cannot be safely associated with the active CCR
session fail visibly rather than being sent to an unintended model.
