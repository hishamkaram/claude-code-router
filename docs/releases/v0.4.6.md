# CCR v0.4.6

## Highlights

- OpenAI-compatible Chat Completions routes now translate image-bearing
  Anthropic `tool_result` blocks instead of returning a 501 compatibility
  error.
- Tool responses remain text-only for provider compatibility, while extracted
  images are sent in a trailing OpenAI user message after all tool responses.
- A live Claude Code model-switch fixture proves that an MCP image tool result
  survives the switch to an OpenAI-compatible alias.

## User-Visible Changes

When Claude Code sends an image inside a tool result to an OpenAI-compatible
alias, CCR preserves the tool response text and sends the image as an
OpenAI-compatible `image_url` user content part. Image-only results use the
visible `[image output]` placeholder in the tool message so tool-call history
remains valid.

The selected alias must be vision-capable. CCR continues to reject image
history for aliases that do not advertise or explicitly enable vision rather
than silently dropping the image.

## Upgrade

```bash
brew upgrade hishamkaram/tap/claude-code-router
ccr version
ccr doctor
```

No database migration is required. Existing aliases that use image input must
retain their vision capability facts or overrides.

## Privacy and Security

- Base64 and URL-backed images use the existing image resolver, size limits,
  HTTPS restrictions, and private-network protections.
- Tool-result image content is not logged or persisted by the conversion path.
- Provider secrets and authentication handling are unchanged.

## Compatibility

- OpenAI-compatible Chat Completions routes translate nested tool-result images
  with visible safe degradation.
- Tool messages remain contiguous before the trailing user message, preserving
  OpenAI tool-call ordering requirements.
- Invalid image sources and non-vision aliases continue to fail visibly.
- Explicit `/compact` context-management edits remain unsupported on
  OpenAI-compatible routes.
- The macOS computer-use helper is source-built only, is not shipped in
  Homebrew or GoReleaser archives, and remains an unsigned preview.

## Verification

Release evidence is recorded in `docs/acceptance/v0.4.6.md`, including direct
gateway tests, the full tagged live suite, and live Claude Code MCP image-tool
coverage across an in-session `/model` switch.

## Known Limits

- Provider-specific OpenAI-compatible implementations may impose additional
  multipart content restrictions; CCR rejects unsafe or unsupported input
  rather than silently dropping it.
- The translation applies to the OpenAI Chat Completions route. Other provider
  protocols retain their own content contracts.
